## 2026.8.23

グラフを表すクラスを実装した。
無向/有向、辺の重みあり/なしの 4 通りに対応できる設計が必要。
検討の結果、4 通りすべてを独立したクラス (`Graph`, `Digraph`, `WeightedGraph<T>`, `WeightedDigraph<T>`) として実装する方針を採用した。
mixed graph はほとんど出題されないこともあり今回は考慮しない。
グラフアルゴリズムは、これらの型を明示せず、適切なコンセプトを課したテンプレート関数として実装する。

#### 検討した案

- 無向を有向の特殊ケース (無向辺は双方向に辺を張った有向辺) と見なして、一つのクラスにまとめる案
  - `Graph` と `Digraph` が型で区別できなくなるので、グラフアルゴリズムの適用範囲を型で示せなくなるのが気になる。また、この方針では無向辺と有向辺を混ぜて add できてしまうので、辺数が何を表すのか (無向辺を +1 or +2 のどちらで数えるのか) が曖昧になる。
- 重みなしを重みありの特殊ケース (重みの型が int で重み 1) と見なし、`using Graph = WeightedGraph<int>` とする案
  - これも上と同様、`Graph` と `WeightedGraph<int>` が型で区別できなくなるのが問題。グラフアルゴリズムの適用範囲を型で示すことができなくなる (e.g., BFS による SSSP は重みなし用)。
- グラフの内部表現は、 `std::vector<std::vector<int>>` による隣接リスト (値は辺の番号) と `std::vector<Edge>` による辺のリストの二つを管理する方針とした。CSR 形式は、辺の追加が終わったあとで構築するひと手間を嫌って避けた。一次元配列による隣接リストの実装[1]は、iterate する辺の順番が add した順番と逆になることが思考のリソースを食いそうなので避けた。

#### コメント

- `num_vertices`, `num_edges` の関数名は Boost Graph Library から拝借した。
- `std::vector` と同じく、隣接辺の iterate 中にグラフを変更すると壊れる。重みの変更だけは安全にできるが、今はその口は用意していない。やるなら `WeightedGraph<T>::set_cost` のような関数を作るのがよさそう。
- 無向グラフの自己ループは `operator[]` の戻り値に二回現れる。この挙動は、`G[u]` が「$u$ から出る "向きつきの辺" を一回ずつなめる」と考えると自然。
